# PG guide pilot: exact briefs and first drafts

These are model-generated drafts for fictional tasks, not writing by Paul Graham or real messages sent by a person. See [the results and method](pg-style-guide-ablation-2026-11-05.md). Both conditions received the same three reference essays; only the added-guide condition received the fixed guide. The condition labels here are disclosed for audit, so this file is not a blind judging packet.

No draft below was revised after generation. Fences preserve the original draft text and paragraph breaks. Scores and practical conclusions are in the results note.

## 1. essay_tools

### Brief

```text
Write a 300-400 word essay for general readers about why a hypothetical neighborhood tool library should start with fewer tools. Its budget buys either 20 frequently requested tools plus maintenance and spare parts, or 60 different tools with little left for upkeep. Borrowers need to know whether a tool is available and usable. Starting small lets organizers learn what is actually borrowed before buying more. A narrow selection can still fail if it omits what the neighborhood needs. Develop an argument from these facts.
```

### Samples only

```text
A neighborhood tool library should begin with tools it can keep working. Given a choice between 20 frequently requested tools with money for maintenance and spare parts, or 60 different tools with little left for upkeep, I would choose the 20.

The case for 60 is easy to see. More kinds of tools mean more kinds of jobs the library might help people do. A list of 60 also looks more useful than a list of 20. But borrowers need to know whether the tool they need is available and usable. The length of the list cannot answer either question.

Maintenance is therefore part of what the library buys when it buys a tool. Spare parts and upkeep help turn an object on a shelf into something a neighbor can use. Spending nearly everything on the initial selection leaves little money to preserve that usefulness. The library could offer more choices while giving borrowers less reason to rely on them.

Starting with 20 also gives organizers a chance to learn. Frequently requested tools are a sensible place to begin, but requests are only an early guide. Once borrowing starts, organizers can see which tools people actually take home. They can use that evidence to decide what to buy next, instead of committing the budget to 60 choices before they have it.

There is a limit to this argument. A small selection can be reliably available, carefully maintained, and still miss what the neighborhood needs. Keeping the wrong tools in good condition does not make them the right tools. Organizers should pay attention both to what gets borrowed and to what people need but cannot find. Otherwise, the borrowing record will tell them only about the choices they happened to offer.

The reason to start small is to make the first purchases useful and the later purchases better informed. Twenty tools are a beginning, not a permanent ceiling. If the library keeps them usable and learns where its selection falls short, it will have a sound basis for growing.
```

### Samples + guide

```text
A neighborhood tool library should start with 20 frequently requested tools and enough money to keep them working. The alternative, 60 different tools with little left for upkeep, looks more generous. But the number of tools on the shelves doesn't tell you how much help the library can give.

A borrower needs to know two things: is the tool available, and does it work? A long list of tools answers neither question. If the tool you need is broken, owning it hasn't done the library much good. Maintenance and spare parts belong in the budget because they help turn a tool the library owns into a tool someone can use.

This changes what counts as a good selection. The aim is to help people get work done. Twenty tools that the library can maintain may do that better than 60 tools it can barely afford to look after. The smaller collection also gives organizers a more manageable starting point for keeping track of what's available and usable.

Starting small has another advantage: it leaves room to learn. Requests are useful evidence, but borrowing shows what people actually take home. Organizers can watch which tools are borrowed often and which stay on the shelf. They can use that knowledge to guide later purchases. Buying all 60 at once would mean making more decisions before having that evidence.

But a small collection isn't automatically a good one. It can be neatly organized, carefully maintained, and still miss what the neighborhood needs. And borrowing records have a limit: people can't borrow a tool the library doesn't offer. An unused shelf tells you something about the tool on it. It tells you nothing about the tool someone wished were there.

The library should therefore begin with the 20 frequently requested tools, fund their upkeep, and keep listening for needs the collection doesn't meet. Expansion should follow both borrowing and those unmet needs.

Starting with fewer tools is a way to make the first purchases useful and the next purchases better informed. The library can earn a larger collection by learning what belongs in it.
```

## 2. essay_repairs

### Brief

```text
Write a 250-350 word essay for general readers about keeping a written list of recurring household repairs. In this hypothetical household, people remember the latest annoyance and forget older problems. A shared list records what broke, how often it recurs, and whether it has been fixed. It can help separate repeated problems from one-off nuisances. Recording everything without ever reviewing the list would waste effort. Explain why a small, regularly reviewed list might help, without claiming that a list repairs anything by itself.
```

### Samples only

```text
The household repair that gets the most attention is often the one that annoyed someone last. That makes sense when something has just broken. It makes less sense when the latest nuisance pushes an older, recurring problem out of everyone’s memory.

A small written list can help. It gives the household somewhere to keep problems between the moment someone notices them and the moment someone can deal with them. Otherwise, remembering becomes another job, and each person may assume someone else is doing it.

The useful details are simple: what broke, how often it has happened, and whether it has been fixed. If the same problem returns, add that to the existing entry. Over time, the list can show a difference that memory tends to blur. One thing was irritating once. Another keeps failing.

That difference helps people decide where to spend their attention. The latest annoyance may still deserve to come first. But it can be considered alongside the problems that have become so familiar that nobody mentions them anymore. A shared list also lets everyone see whether a repair is still waiting or has already been done.

Of course, writing things down can become its own kind of avoidance. A growing record that nobody reads takes effort without helping anyone choose what to do. The list needs a regular review, even a brief one, to remain useful. Check what is still broken, what has returned, and what can be marked fixed.

Keeping the list small makes that review easier. It only needs enough detail to support the next decision.

A list cannot stop a leak or mend a hinge. Someone still has to do the work. What it can do is keep yesterday’s problem available for consideration today, after the annoyance has faded but the need for a repair has not.
```

### Samples + guide

```text
The latest thing to go wrong in a house has an advantage: people still remember it. A sticking drawer can get more attention than a leak that has returned three times, simply because someone fought with the drawer this morning.

Memory makes a poor repair list. Each new annoyance pushes older ones aside. A problem can disappear from conversation long before it disappears from the house.

A small shared list gives those older problems somewhere to stay. Each entry needs only a few things: what broke, how often it has happened, and whether it has been fixed. Everyone can see it and add to it. The point is to leave enough information for the next person who has to decide what needs attention.

Why record how often something happens? Because repetition changes the question. A cupboard door that came loose once might need a simple fix. A door that keeps coming loose deserves another look. If each episode is remembered separately, people may keep treating the same problem as a fresh nuisance. Putting the episodes together makes the pattern easier to see.

But a list can become another household chore with no useful result. Recording every squeak and wobble takes time. If nobody reads the entries again, that time has bought very little.

The list therefore needs a regular review. Keep it short enough that reading it feels easy. Check which repairs are finished, which problems have returned, and which small annoyances can wait. A brief review can help the household choose its next job without letting the most recent complaint choose for it.

The list itself will never tighten a screw or stop a leak. Its useful job is smaller: keeping a recurring problem in view long enough for someone to deal with it.
```

## 3. essay_class

### Brief

```text
Write a 250-350 word essay for general readers about a hypothetical beginner's woodworking class choosing between covering many techniques briefly and helping students complete one simple box. Finishing the box exposes problems in measuring, joining, and fitting a lid that watching a demonstration may not expose. A finished box does not establish mastery of woodworking. Some techniques will still need separate teaching later. Make a case for finishing one modest project first, with appropriate limits.
```

### Samples only

```text
A beginner’s woodworking class could spend its first few weeks introducing tools and techniques. Students would see a lot, and each lesson might make sense. But I’d start by helping everyone finish one simple box.

A box gives each lesson a job. Measuring matters because the pieces have to meet. Joining matters because they have to stay together. Fitting a lid matters because someone will eventually try to close it.

Watching a teacher do these things can leave a beginner with a mistaken sense of understanding. The teacher measures, cuts, and fits a piece, and the result seems obvious. When students try it themselves, they have to make decisions the demonstration may have passed over. Which edge should they measure from? What should they do when two pieces don’t line up? Why does a lid that looked right fail to close?

Finishing brings these questions together. A small error can travel through the work and appear somewhere else. Students get to follow it back, make a correction, and see whether the correction helps. They also learn what it takes to carry a project past the point where its remaining problems become annoying.

The box should be modest enough to finish. An ambitious design could bury the useful lessons under too many new demands. The aim is to give beginners a whole piece of work they can understand.

And a finished box proves only so much. It doesn’t establish mastery of woodworking, or even show that a student could make the same box without help. Some techniques won’t come up at all. Others will need separate teaching and more practice later.

But those later lessons will have somewhere to land. Students will have questions from their own work, and a reason to care about the answers. They’ll also have a box whose lid they can open and close.
```

### Samples + guide

```text
A beginner’s woodworking class has a choice: show students many techniques, or help them finish one simple box. I’d start with the box.

A demonstration can make a task look clear before you’ve understood it. You watch someone measure a board, make a joint, and fit a lid. Each step seems reasonable. But watching gives you few chances to discover what you’ve missed.

A box gives you those chances. You measure the pieces, then find that they don’t meet as you expected. You make a joint that looks fine on its own, then struggle to bring the sides together. You fit the lid and discover that “about the right size” leaves a question: does it actually fit?

These problems give the teacher something specific to teach. A lesson about measuring now answers a question the student has encountered. The student can try the advice and see whether it helps. There’s a short path from explanation to consequence.

Why insist on finishing? Because stopping early can hide the problems that connect the steps. The sides may look good laid out on a bench. Putting them together asks more of them. Adding a lid asks more again. Finishing means carrying earlier decisions far enough to find out whether they worked.

Of course, a finished box proves very little about mastery. A student might need help at every stage. One kind of joint won’t teach every other kind, and some techniques will need separate lessons later. The box is a small beginning, not a certificate of competence.

But it gives later lessons somewhere to attach. Students have an object they understand through making it, including the places where they got stuck. They can ask better questions because they’ve met a few real problems.

The first project should be modest enough to finish and demanding enough to reveal mistakes. A simple box can do both.
```

## 4. post_bookclub

### Brief

```text
Write a 120-180 word public post proposing that a hypothetical neighborhood book club discuss one book a month rather than three. Several members cannot finish three books. Reading one shared book could give everyone a common starting point for discussion. People who want to read more can do so separately. A slower schedule will not solve a poorly chosen book or an unfocused discussion. The proposal has not been approved. Invite readers to consider the tradeoff without inventing a vote, date, or outcome.
```

### Samples only

```text
I'd like to propose that our neighborhood book club discuss one book a month instead of three.

Several members can't finish three books. With one shared book, more people could finish the reading and come to the discussion with a common starting point. We'd have more time to think about what we read and hear what others made of it.

People who want to read more could still do so separately. The club's schedule doesn't have to set the pace for all our reading.

There is a tradeoff. We'd discuss fewer books together, and a slower schedule wouldn't fix a poorly chosen book or an unfocused discussion. We'd still need to choose carefully and give the conversation some direction.

This is a proposal, and it hasn't been approved. Would the chance for more members to finish the same book be worth covering fewer books as a group?
```

### Samples + guide

```text
I propose that our neighborhood book club discuss one book a month instead of three. Several members can't finish three books, and that makes it harder for them to join the conversation.

One shared book could give everyone a common starting point. If more people have time to finish it, more people can bring their own questions, notice different things, and follow the discussion without worrying about what they haven't read. Anyone who wants to read more can still do so separately.

A slower schedule has limits. It won't make a poorly chosen book more interesting or give an unfocused discussion a direction. We'd still need to choose books carefully and put some thought into the conversation.

This proposal hasn't been approved. The tradeoff is worth considering: we'd cover fewer books together, but we might give more members a chance to take part. What would we gain, and what would we miss?
```

## 5. post_garden

### Brief

```text
Write a 120-180 word public post about a hypothetical community garden keeping brief weekly notes on watering, weather, and plant condition. Memory can confuse which bed had a problem and when. Shared notes let volunteers compare what happened and choose what to investigate next. They do not prove that watering or weather caused a change. The notes should stay short enough that people actually keep them. Make the case without inventing yields, statistics, or results.
```

### Samples only

```text
It’s easy to remember that a garden bed looked dry. It’s harder to remember which bed it was, whether anyone had watered it, and whether that was before or after the hot weather.

A community garden could keep a few shared notes each week: which beds were watered, what the weather was like, and how the plants looked. A few lines would give volunteers something to compare when memory gets muddled.

If plants in one bed looked worse, the notes could help people choose what to investigate next. Was that bed getting less water? Were other beds showing the same change?

The notes wouldn’t settle those questions. A change after watering or a hot week doesn’t prove that either caused it. But a shared record could help volunteers ask more precise questions.

Keep it short. The notes only help if people keep writing them. A few useful observations each week are enough to start.
```

### Samples + guide

```text
A community garden could learn a lot from a few lines of notes each week: which beds were watered, what the weather was like, and how the plants looked.

Memory seems good enough until someone asks which bed had the yellow leaves. Was it the one by the gate? And was that before or after the hot spell? People can remember the same problem and place it in different weeks.

Shared notes give volunteers something to compare. If a bed looks worse, they can look back at its watering, the weather, and earlier signs of trouble, then choose what to investigate next.

The notes don't prove what caused a change. A plant looking better after watering doesn't establish that watering explains it. The record helps people ask better questions.

But the record only helps if people keep it. A few useful lines each week are enough. Writing them should leave plenty of time for the garden.
```

## 6. post_cooking

### Brief

```text
Write a 120-180 word public post for beginner cooks about repeating a few dishes before constantly trying new recipes. In this hypothetical example, repeating a dish makes it easier to notice what changes when the cook adjusts one ingredient or step. Trying something new can still be enjoyable and useful. The idea is to make learning easier, not to ban variety or claim that repetition guarantees skill. Do not invent a personal cooking story.
```

### Samples only

```text
If you're learning to cook, give a few dishes a second or third turn before moving on to the next recipe.

The first time you make a dish, there's a lot to keep track of. You're reading instructions, finding ingredients, and deciding whether the pan is hot enough. When you make it again, some of those decisions are familiar. You have more attention left to notice what's happening.

That makes it easier to learn from a small change. Try a little less lemon, or cook the onions longer. If you change one thing at a time, you have a better chance of understanding what changed the taste.

New recipes can be fun, and they can teach you things your usual dishes won't. Leave room for them too. But give yourself a few familiar dishes to practice with. Repeating them won't guarantee skill. It can simply make each attempt easier to learn from.
```

### Samples + guide

```text
You can make cooking easier to learn by making a few dishes more than once. A familiar dish gives you something to compare your next attempt with.

Suppose you make the same soup again, but add less salt. You have a better chance of noticing what the salt changes because the other ingredients and steps are familiar. If you change the recipe, the heat, and half the ingredients at once, it's harder to tell which change caused the result.

That's a reason to keep a few dishes in rotation while you're learning. Pick something you like eating, make it again, and adjust one ingredient or step. Notice what happens. You don't have to improve it every time for the comparison to be useful.

Trying new recipes can still be fun and teach you things. Repetition simply gives you fewer things to figure out at once. Leave room for both.
```

## 7. email_seeds

### Brief

```text
Write a 100-150 word email to neighborhood volunteers proposing a seed library that starts with five requested vegetable varieties and clear labeling rather than a large assortment that nobody can identify. This is a proposal, not an agreed decision. There is limited storage space. The organizers need volunteers to suggest which five varieties neighbors would actually use. A small selection can still be wrong. Be considerate and direct. Do not invent names, deadlines, meetings, costs, or a sign-off identity.
```

### Samples only

```text
Hello everyone,

I’d like to propose starting a neighborhood seed library with five vegetable varieties that neighbors have asked for, each clearly labeled. We have limited storage space, and a small selection with labels people can read and understand seems more useful than a large assortment nobody can identify.

But choosing just five won’t help if we choose the wrong five. Could you suggest which varieties your neighbors would actually grow and use? Please be as specific as you can, so we can distinguish a request for a particular variety from a general interest in a vegetable.

Your suggestions would help us decide what to include. The proposal is to start small, choose based on what neighbors want, and make every packet easy to identify.
```

### Samples + guide

```text
Hi everyone,

I’d like to propose starting a neighborhood seed library with five vegetable varieties that neighbors have asked for, with clear labels so people know what they’re taking and planting.

Storage space is limited. A large assortment might look generous, but it won’t be much use if nobody can identify the seeds. A small, clearly labeled selection would be easier to store and use.

But a small selection can still be wrong. Five varieties that sit untouched would take up less space without helping anyone grow vegetables.

Could you suggest which five varieties your neighbors would actually use? Please base your suggestions on what you’ve heard people ask for or know they grow. That would give us a useful starting point for deciding what to include.

Thanks for helping shape the proposal.
```
